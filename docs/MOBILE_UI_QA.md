# 手机竖屏 UI 改造与验证记录

日期：2026-09-15。代码基线：`1aacb32`（项目版本 0.5.2）。

## 交付范围

仅为手机竖屏设计一个页面布局。账号使用单列卡片，课程使用紧凑列表，批量操作固定在底部；设置、添加账号、二维码、签到码和手势签到改为底部弹层，签到记录使用底部抽屉。保留浅色与深色主题。

保留原有页面路由与全部功能入口：本站登录/注册/资料、某星账号添加/移除/选择/同步、单账号及批量签到/扫码、监听/取消监听、课程/活动/课程签到、设置/重置、签到历史、日志/清空/折叠、帮助及外部项目链接。

未增加依赖，未修改 `server/`、`stores/`、`prisma/`、`utils/request.ts`、`package.json`、锁文件或 `nuxt.config.ts`。逐个比较改动 Vue 文件的脚本块，仅 `app.vue` 调整主题尺寸，以及 `AccountItem.vue` 增加显式选择事件；业务方法保持原样。新增 `plugins/mobileViewport.client.ts` 只维护可视视口高度、软键盘底部偏移和底部操作栏可见性。

`app.vue` 显式指定 Naive UI 的 `cls-prefix="n"`，解决本地运行时出现的组件类名前缀为空、控件样式未正确应用的问题。

## 验证方式

1. 实际 Nuxt 页面检查登录界面与控件样式。
2. 隔离预览加载仓库中实际 Vue 页面/组件、Naive UI、账号与日志 store；模拟 Nuxt 路由/认证、接口响应和消息服务。使用虚构账号、课程与签到记录，没有连接真实签到服务或数据库。
3. 浏览器读取 DOM 与元素尺寸，检查布局及入口交互。
4. 最终执行 `pnpm.cmd run build`：退出码 **0**，客户端、SSR 与 Nitro 产物生成成功。
5. `git diff --check` 通过；逐个比较 Vue 脚本块，并核对业务文件未改动。

## 竖屏尺寸检查

| 视口（CSS px） | 页面可用宽度 | 页面滚动宽度 | 横向溢出 | 主要按钮最小高度 | 批量栏底边 |
| --- | ---: | ---: | --- | ---: | ---: |
| 320 × 568 | 305 | 305 | 无 | 44 | 568 |
| 375 × 667 | 360 | 360 | 无 | 44 | 667 |
| 390 × 844 | 375 | 375 | 无 | 44 | 844 |
| 430 × 932 | 415 | 415 | 无 | 44 | 932 |

预览浏览器的纵向滚动条占用 15px；上表按实际可用宽度测量。没有设计或验收桌面与横屏布局。

320 × 568 下设置弹层顶部至少留出 12px，正文可纵向滚动；设置数字输入的加减按钮、关闭与保存/重置按钮均为 44px 高。输入字号为 16px。390 × 844 下签到记录抽屉约 717px 高，签到码弹层约 222px 高，二维码弹层约 612px 高，均贴合视口底部。

## 已检查的界面交互

- 选择账号及全选会更新选择数量；点击签到操作不会顺带改变账号选择。
- 普通单账号/批量签到使用模拟响应进入原有处理与日志流程。
- 课程详情、长课程名称、活动列表与活动签到按钮正常呈现。
- 设置弹层完整呈现原有字段，保存模拟设置后原有日志输出“保存成功”，关闭按钮正常工作。
- 签到历史的长活动名称、时间与结果在竖屏中呈现。
- 签到码与手势输入弹层正常呈现；签到码输入及提交进入模拟处理流程。
- 二维码弹层保留扫描、图片识别与链接输入区域；展开动画结束后关闭按钮正常工作。未授予摄像头权限或执行真实扫描。
- 空账号页面、添加账号弹层、本站登录/注册、用户菜单及资料页面正常呈现。
- 浅色与深色主题切换正常。

## 验证边界

以上结果证明构建与所列界面布局/模拟交互通过，不证明真实登录、注册、监听、签到、摄像头识别或数据库写入成功。真实手机软键盘与安全区域未进行真机验收。帮助与 404 保留原有内容/操作并使用共用手机样式，未列入独立截图验收。

构建仍提示现有的 Google Fonts 网络不可达、Browserslist 数据陈旧、Sass 旧接口及部分依赖/组件警告，未更改依赖来处理。构建期间曾与本任务开发服务共用 `.nuxt` 缓存而失败，停止已核对的开发服务后重新构建成功。

原有接口与业务问题见 [架构说明](ARCHITECTURE.md) 和 [接口清单](FRONTEND_API.md)，本次 UI 改造未修复或扩展这些逻辑。
